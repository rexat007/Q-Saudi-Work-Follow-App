## 3. Core identity matrix

All identifiers below are currently **plain TypeScript strings**, serialized as string fields/path segments. A required property checks structure at compile time; it neither distinguishes entity ID kinds nor proves nonempty content, existence, authorization, project ownership or uniqueness. The table records current generation; it does not mandate that all stored IDs match a new-record generator pattern. Existing persisted IDs remain valid in their existing contexts; existing validation/security checks still apply, and no malformed payload is newly accepted by this statement.

## 4. Binding identity and relationship rules

1. A domain ID denotes identity, not a display value. ProjectId is not Project name; DriverId is not national ID; TruckId is not plate; MaterialId is not code/name; CarrierId is not carrier source/display text.
2. Natural keys may be normalized for lookup/resolution. A successful lookup returns a referenced identity; it does not license returning the natural value as a fabricated canonical ID. New identity creation must continue through the existing owning creation path.
3. Existing persisted IDs and their wire/path serialization remain unchanged. No branding, new required format, rewrite or universal prefix rejection is introduced by P1-U1.
4. Document ID and domain ID coincide only in the contexts documented above. A membership/affiliation key is participant identity plus enclosing Project scope, not a new redundant composite identity field. Natural lookup keys and temporal pointer keys have different mappings.
5. GLOBAL IDENTITY is the shared master profile; it does not own project participation, operational carrier affiliation, assignment, allocation or pricing. Optional global Truck.primaryCarrierId does not override project affiliation.
6. PROJECT MEMBERSHIP answers participation/authorization for Project P. It does not copy the global profile or establish a carrier/driver/truck/material operational assignment. `membership != affiliation`.
7. CARRIER AFFILIATION identifies the current project-local carrier for a Driver or Truck. It does not itself select a paired vehicle/driver or material. `affiliation != assignment`.
8. DRIVER-TRUCK ASSIGNMENT is a temporal interval with participant-specific active slots. Existing production code proves project-scoped active-slot cardinality, not globally exclusive assignment across all Projects. `assignment != allocation`.
9. TRUCK-MATERIAL ALLOCATION is a separate temporal interval and active Truck material slot. It does not require a Driver assignment merely to allocate, and contains no pricing/rate authority. Existing code/tests preserve independent allocation across carrier/driver changes; this contract does not invent cascade changes.
10. Missing/pending selections may exist in forms or read projections; they must not be relabeled as valid persisted identities. Resolution candidates, aliases, form keys and legacy project IDs retain their evidenced contexts until the owning phase converges them.

## 7. Stored / input / projection boundary rules

A stored entity is not automatically a create DTO, an update DTO, a server-authenticated command or a UI selection. A create command may carry natural-key input before a server-generated identity exists; its caller-provided ID never establishes allocation authority. An update command must be bounded by immutable identity/natural-key and ownership rules of the owning service; `Partial<Entity>` alone is not a safe update contract. This documentation introduces no replacement DTO.

A UI projection may contain local `id`, labels, optional references, counts, integrity flags or a nullable selection. Those do not become canonical profile fields or keys. A persistence DTO may carry serverTimestamp/serialized metadata and a path-implied key; it is not automatically a domain entity. Firestore `snap.data() as Entity` is a TypeScript cast, not runtime validation; `sanitizeUndefined` cleans representation but does not validate a full schema or FK.

Current boundaries include inline create/update inputs in globalIdentity.repository, typed intake commands, any-typed Admin provisioning inputs, ProjectEntity/Omit/Partial repository inputs, and the typed ProjectFleetReadModelReadContext. They are evidenced coexistence, not permission to merge their responsibilities. Future convergence must name the trust boundary, preserve exact wire/storage behavior and identify every affected consumer before adding validators or changing optionality.
